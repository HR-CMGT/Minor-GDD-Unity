### Milestone 1: Fluid Responsive Mobile HUD & Touch Controls
Since your 2D game runs on mobile devices with diverse aspect ratios (16:9, 19.5:9, 20:9, 4:3) and hardware cutouts (notches, Dynamic Islands, camera punch holes), all HUD elements must dynamically adapt **without hardcoding aspect ratios or forcing black borders**.

1. **Canvas Scaler Setup (Fluid Adaptation):**
   - Create a Canvas: **GameObject -> UI -> Canvas**.
   - Configure the `Canvas Scaler`:
     - **UI Scale Mode:** `Scale With Screen Size`
     - **Reference Resolution:** `1920 x 1080` (Landscape) or `1080 x 1920` (Portrait)
     - **Screen Match Mode:** `Match Width Or Height`
     - **Match:** `1.0` (Match Height) for Landscape mobile games, or `0.0` (Match Width) for Portrait mobile games.
     - *Why this works without black bars:* Matching Height in landscape keeps the vertical playfield constant while UI corner anchors dynamically spread across wider phones (like 20:9 Galaxy) or contract on square tablets (4:3 iPad) without letterboxing!
2. **Safe Area Fitter Component:**
   - Create a child GameObject named `SafeAreaPanel` under your Canvas. Set its RectTransform to **Full Stretch** (`Min(0,0)`, `Max(1,1)`).
   - Create and attach `SafeAreaFitter.cs` to `SafeAreaPanel`:
     ```csharp
     using UnityEngine;

     [RequireComponent(typeof(RectTransform))]
     public class SafeAreaFitter : MonoBehaviour
     {
         private RectTransform _rectTransform;
         private Rect _lastSafeArea = Rect.zero;
         private Vector2Int _lastScreenSize = Vector2Int.zero;
         private ScreenOrientation _lastOrientation = ScreenOrientation.AutoRotation;

         void Awake()
         {
             _rectTransform = GetComponent<RectTransform>();
             ApplySafeArea();
         }

         void Update()
         {
             // Detect phone orientation flips (180deg) or foldable device un-folding
             if (Screen.safeArea != _lastSafeArea ||
                 Screen.width != _lastScreenSize.x ||
                 Screen.height != _lastScreenSize.y ||
                 Screen.orientation != _lastOrientation)
             {
                 ApplySafeArea();
             }
         }

         void ApplySafeArea()
         {
             _lastSafeArea = Screen.safeArea;
             _lastScreenSize = new Vector2Int(Screen.width, Screen.height);
             _lastOrientation = Screen.orientation;

             Vector2 anchorMin = _lastSafeArea.position;
             Vector2 anchorMax = anchorMin + _lastSafeArea.size;

             anchorMin.x /= Screen.width;
             anchorMin.y /= Screen.height;
             anchorMax.x /= Screen.width;
             anchorMax.y /= Screen.height;

             _rectTransform.anchorMin = anchorMin;
             _rectTransform.anchorMax = anchorMax;
         }
     }
     ```
3. **Construct the 4 Mobile HUD Corners (Inside `SafeAreaPanel`):**
   - **Top-Left (Pause Button):** Anchor `(0, 1)`. Minimum touch target at least **88 x 88 px** (44pt).
   - **Top-Right (Coins / Gems Counter):** TextMeshProUGUI anchored to `(1, 1)`. Uncheck **Raycast Target**.
   - **Bottom-Left (Touch Joystick for 2D Movement):**
     - Add an Image for the joystick background and an inner handle.
     - Attach Unity's New Input System component `OnScreenStick` (`UnityEngine.InputSystem.OnScreen.OnScreenStick`).
     - Set **Control Path** to `<Gamepad>/leftStick` (or your Player Input Action map move binding).
     - Minimum touch radius: at least **140 x 140 px**.
   - **Bottom-Right (Jump Button):**
     - Add a Button with `OnScreenButton` component attached.
     - Set **Control Path** to `<Gamepad>/buttonSouth` (or Player Jump action).
     - Minimum touch target: at least **96 x 96 px**.
4. **Universal Anchor Playbook (How to Anchor Every Element Cleanly):**
   Follow these 4 anchor recipes so elements never stretch weirdly across different aspect ratios:
   - **Corner Controls (Pause, Coins, Joysticks, Jump Button):**
     - *Anchor:* Point Anchor to respective corner (Top-Left `Min(0,1), Max(0,1)`, Top-Right `Min(1,1), Max(1,1)`, Bottom-Left `Min(0,0), Max(0,0)`, Bottom-Right `Min(1,0), Max(1,0)`).
     - *Pivot:* Matches the corner (e.g. `(0, 1)` for top-left).
     - *Size:* Fixed width & height (e.g. 96 x 96 px).
     - *Behavior:* Pins to the device edge. Never stretches or deforms.
   - **Banners & HUD Bars (Top Status Strip, Bottom Toolbars):**
     - *Anchor:* Horizontal Stretch (`Min(0,1), Max(1,1)`).
     - *Pivot:* `(0.5, 1)`.
     - *Size:* Fixed height (e.g. 80px), left/right margins set to 0.
     - *Behavior:* Fluidly spans screen width across 16:9, 20:9, or 4:3 without vertical distortion.
   - **Center Popups (Dialogues, Pause Menu, Inventory, Victory Modals):**
     - *Anchor:* Middle-Center (`Min(0.5, 0.5), Max(0.5, 0.5)`).
     - *Pivot:* `(0.5, 0.5)`.
     - *Size:* Fixed reference size (e.g. 600 x 400 px).
     - *Behavior:* Stays dead-center. Never gets distorted or stretched on ultra-wide or square screens.
   - **Square & Circular Icons (Minimap, Avatar Portrait, Ability Circles):**
     - *Component:* Attach `AspectRatioFitter` to the RectTransform.
     - *Aspect Mode:* `Fit In Parent` (or `Height Controls Width`).
     - *Aspect Ratio:* `1.0`.
     - *Behavior:* Guarantees a perfect 1:1 circle or square on ANY screen ratio. Never squashes into an oval!
5. **9-Sliced Sprites for Responsive 2D Panels:**
   - For UI panels, dialogue boxes, and button graphics: select sprite in Project view, open **Sprite Editor**, and drag the green 4-way border handles inward (e.g., 12px borders).
   - On the UI Image component, set **Image Type** to `Sliced`.
   - Now UI boxes adapt and stretch to any mobile screen resolution without blurry or distorted pixel borders!
6. **TextMeshPro Auto-Sizing (Zero-Overflow Text):**
   - For dynamic labels, score numbers, and dialogue text: check **Auto Size** in the `TextMeshProUGUI` component.
   - Set **Min Size = 16** and **Max Size = 32**. Text will scale down gracefully on compact screens without clipping or truncating!
7. **Mobile Optimization & Testing:**
   - Uncheck **Raycast Target** on all background images, icons, and non-interactive text labels.
   - Open Unity's **Device Simulator** (**Window -> General -> Device Simulator**).
   - Switch between **Apple iPhone 15 Pro** (Dynamic Island notch), **Galaxy S24** (20:9), and **Apple iPad Air** (4:3 tablet). Verify that all buttons dynamically reposition, never collide with cutouts, and keep their designed proportions!

### Milestone 2: 2D World Space Overhead Health Bar (Sorting & Flip Fix)
In a 2D game, overhead health bars live inside 2D scene space above character sprites. They do **not** use 3D camera billboarding; instead, they require **2D Sorting Layers** (so they don't hide behind sprites or tilemaps) and **Sprite Inversion Protection** (so the health bar does not mirror backwards when a 2D character turns left).

1. On an Enemy or Player prefab, add a child GameObject named `WorldSpaceHealthBar`.
2. Add a `Canvas` component:
   - Set **Render Mode** to `World Space`.
   - Set **Sorting Layer** to `UI` (or your top Sprite sorting layer) and **Order in Layer** to `100`.
   - Set RectTransform size to `200 x 30` and scale to `(0.01, 0.01, 0.01)`.
   - Position it above the character's head.
3. Add a child UI `Slider` for the health bar fill (remove the default handle child if not needed).
4. Attach `WorldSpaceHealthBar2D.cs` to prevent the health bar from flipping backwards when the 2D character changes facing direction (`localScale.x = -1`):
   ```csharp
   using UnityEngine;

   [RequireComponent(typeof(Canvas))]
   public class WorldSpaceHealthBar2D : MonoBehaviour
   {
       [SerializeField] private string sortingLayerName = "UI";
       [SerializeField] private int orderInLayer = 100;

       void Awake()
       {
           Canvas canvas = GetComponent<Canvas>();
           canvas.overrideSorting = true;
           canvas.sortingLayerName = sortingLayerName;
           canvas.sortingOrder = orderInLayer;
       }

       void LateUpdate()
       {
           // Prevent health bar from mirroring when parent 2D character flips scale.x
           if (transform.parent != null)
           {
               Vector3 scale = transform.localScale;
               float parentDir = Mathf.Sign(transform.parent.lossyScale.x);
               scale.x = Mathf.Abs(scale.x) * parentDir;
               transform.localScale = scale;
           }
       }
   }
   ```

### Milestone 3: Decoupled UI Event Listener
- Create `HealthBarUI.cs` and attach it to your HUD Health Slider:
  ```csharp
  using UnityEngine;
  using UnityEngine.UI;
  using TMPro;

  public class HealthBarUI : MonoBehaviour
  {
      [SerializeField] private Slider healthSlider;
      [SerializeField] private TextMeshProUGUI healthText;
      [SerializeField] private PlayerHealth playerHealth;

      void OnEnable()
      {
          if (playerHealth != null)
          {
              playerHealth.OnHealthChanged += UpdateHUD;
          }
      }

      void OnDisable()
      {
          if (playerHealth != null)
          {
              playerHealth.OnHealthChanged -= UpdateHUD;
          }
      }

      private void UpdateHUD(int current, int max)
      {
          healthSlider.maxValue = max;
          healthSlider.value = current;
          healthText.SetText("HP: {0} / {1}", current, max);
      }
  }
  ```

### Milestone 4: Cross-Platform JSON Persistence Service
- Create `SaveData.cs` to hold your game progress:
  ```csharp
  using System;
  using System.Collections.Generic;

  [Serializable]
  public class SaveData
  {
      public string playerName = "Player";
      public int highscore = 0;
      public int unlockedLevel = 1;
      public List<string> unlockedAbilities = new();
  }
  ```
- Create the static service `SaveSystem.cs`:
  ```csharp
  using System.IO;
  using UnityEngine;

  public static class SaveSystem
  {
      private static string FilePath =>
          Path.Combine(Application.persistentDataPath, "savedata.json");

      public static void Save(SaveData data)
      {
          string json = JsonUtility.ToJson(data, true);
          File.WriteAllText(FilePath, json);
          Debug.Log($"[SaveSystem] Saved to: {FilePath}");
      }

      public static SaveData Load()
      {
          if (!File.Exists(FilePath))
          {
              Debug.LogWarning("[SaveSystem] No save file found. Returning new SaveData.");
              return new SaveData();
          }

          string json = File.ReadAllText(FilePath);
          return JsonUtility.FromJson<SaveData>(json);
      }
  }
  ```
- Test saving when killing an enemy or reaching a checkpoint, and load on `Start()`. Stop and restart Play Mode to verify data persists!

### Unity 6 Golden Rules for 2D Mobile Scalable UI & Persistence:
1. **Canvas Scaler for Mobile (Fluid Adaptation):** Set `Scale With Screen Size` (`1920 x 1080` for landscape, `1080 x 1920` for portrait). Use `Match Height = 1.0` in landscape so top/bottom HUD elements never clip, allowing the UI to fluidly adapt across all resolutions without hardcoding aspect ratios or forcing black bars.
2. **Safe Area Fitter:** Never anchor interactive buttons directly to Canvas corners on mobile. Place them inside a `SafeAreaPanel` using `Screen.safeArea` to avoid notches and Dynamic Island cutouts.
3. **Touch Ergonomics & Input System:** Use `OnScreenStick` and `OnScreenButton` for 2D mobile touch controls. Buttons must be at least **44 x 44 pt (88 x 88 px at 1080p)** with at least 8-12px padding between buttons to prevent fat-finger mis-clicks.
4. **9-Sliced 2D UI Sprites:** Set 4-way borders in Sprite Editor and set `Image Type = Sliced` on UI panels and buttons so backgrounds stretch smoothly across wide mobile resolutions without pixel distortion.
5. **2D World Space UI Sorting:** Overhead health bars in 2D need `canvas.overrideSorting = true`, `sortingLayerName = "UI"`, and `sortingOrder = 100` so they never render behind sprites or tilemaps. Keep scale positive on X even when parent sprite flips.
6. **Mobile 60 FPS Target:** Mobile Unity defaults to 30 FPS. Add `Application.targetFrameRate = 60;` in `Awake()` on game boot to ensure fluid 60 FPS touch response.
7. **Raycast Target Optimization:** Uncheck `Raycast Target` on all decorative images, backgrounds, and non-interactive text labels to save mobile CPU cycles during touches.
8. **TextMeshPro:** Always use `TextMeshProUGUI` instead of legacy `Text`. Use `SetText()` instead of string concatenation `+` to eliminate garbage collection.
9. **Decoupled Architecture:** UI components subscribe via `+=` in `OnEnable()` and unsubscribe via `-=` in `OnDisable()`.
10. **JSON vs PlayerPrefs:** Reserve PlayerPrefs strictly for volume/resolution settings. Use `JsonUtility` + `Application.persistentDataPath` for all game state.
11. **Mobile Auto-Save:** Mobile players don't click "Quit Game"; they switch apps or receive phone calls. Implement `void OnApplicationPause(bool pause) { if (pause) SaveSystem.Save(data); }` in your GameManager.
12. **Sub-Canvas Mesh Isolation:** Put static frames on a `Static_HUD` and rapidly updating health/score text on a `Dynamic_HUD` sub-canvas so mesh rebuilds never rebatch the entire UI.
13. **2D Sprite Atlas Batching:** Pack all HUD buttons and icons into a Sprite Atlas (`Window > 2D > Sprite Atlas`) to reduce mobile GPU draw calls from 40+ to 1-2 draw calls.
