Lesson 1.1 Curriculum Comparison

Minor Game Design & Development - Unity 6 (6000.x)

OLD WAY NEW REVISED WAY
1. Introduction & Learning Goals

Orientation and technical scope of Lesson 1

Old Way

Original Repository Content:

  • No learning objectives listed anywhere in the document.
  • Jumped straight into downloading packages and opening scenes without architectural context.
  • No explanation of what engineering patterns students should look for.
Why the Old Way Caused Confusion:
Students entered the exercise without knowing what core skills they were practicing. They treated the class as "fixing broken buttons" rather than learning the Unity component model and script execution flow.

New Revised Structure:

  1. Component Model: Master the GameObject-Component-Prefab hierarchy.
  2. Script Lifecycle: Correctly apply Awake, Start, Update, and FixedUpdate.
  3. Input & Physics: Drive a 2D character using Rigidbody2D, Collider2D, and the new Input System.
  4. Dynamic Framing: Configure a smooth 2D follow camera with Cinemachine.
Why This Is Better:
Provides explicit engineering milestones up front. Students understand that physics separation and input callbacks are the core learning goals.
2. Project Setup & Package Workflow

Template selection and Package Manager setup

Old Way

Original Instructions:

  1. Create a new 2D project.
  2. Open Package Manager, switch to Unity Registry.
  3. Install Input System and Cinemachine.
Why the Old Way Caused Confusion:
Installing the Input System triggers a modal prompt: "This project uses the new input system backend. Restart editor?". Beginners often clicked "No" or experienced editor freezes, resulting in non-functional keyboard input.

New Revised Instructions:

  1. Create a project using the 2D (URP) template in Unity Hub.
  2. Open Window > Package Manager and switch to Packages: Unity Registry.
  3. Install Input System → Click Yes when prompted to restart the backend.
  4. Install Cinemachine.
  5. Import basics1.unitypackage via Assets > Import Package > Custom Package.
Why This Is Better:
Explicitly warns students about the mandatory restart prompt and specifies URP template defaults, preventing missing render pipelines and input lockups.
3. Scene Hierarchy & Separation of Concerns

Player object architecture

Old Way

Original Structure:

Placed SpriteRenderer, BoxCollider2D, Rigidbody2D, Animator, and scripts on a single GameObject.

Why the Old Way Caused Bugs:
When students flipped the sprite or animated local scale (squash and stretch), the physics Collider scaled and rotated along with the graphics, causing the player to fall through platforms or get stuck in walls.

New Standard Hierarchy:

[Player] (Root: Rigidbody2D, BoxCollider2D, PlayerController2D, PlayerInput)
  └── [Graphics] (Child: SpriteRenderer, Animator)
  └── [GroundCheck] (Child: Empty GameObject at foot level)
Why This Is Better:
Strict Separation of Concerns: The Root handles physics and position; the Graphics child handles visual scale and sprite flips without altering collision boundaries.
4. C# Controller Implementation

PlayerController2D architecture

Old Way

Original Approach:

  • Zero code provided in the markdown document.
  • Told students: "Open PlayerStart.cs and code the Jump function, Move function, ResetPlayer function..." without guidance.
Why the Old Way Failed:
Students guessed how to handle velocity, wrote input polling in FixedUpdate (missed keypresses), or mutated transform.position on Rigidbodies (broke physics interpolation).

New Production C# Standard:

public class PlayerController2D : MonoBehaviour {
    void Awake() {
        rb = GetComponent<Rigidbody2D>();
        rb.freezeRotation = true; // Prevents tipping over
    }
    public void OnMove(InputValue val) => moveInput = val.Get<Vector2>();
    public void OnJump(InputValue val) {
        if (val.isPressed && isGrounded) jumpRequested = true;
    }
    void Update() {
        isGrounded = Physics2D.OverlapCircle(groundCheckPoint.position, 0.25f, groundLayer);
    }
    void FixedUpdate() {
        rb.velocity = new Vector2(moveInput.x * moveSpeed, rb.velocity.y);
        if (jumpRequested) { rb.velocity = new Vector2(rb.velocity.x, jumpForce); jumpRequested = false; }
    }
}
Why This Is Better:
Input is polled responsively in Update(), physics velocities are applied deterministically in FixedUpdate(), and OnDrawGizmosSelected gives visual groundcheck debugging.
5. Assignment Workflow & Scope

Milestone pacing and core mechanics

Old Way

Original Scope:

A sprawling checklist asking Week 1 students to implement:

  • Spritesheet slicing and manual Animator controllers
  • 2D Joints and Physics Materials
  • Sprite Shapes and Tilemaps
  • Platform Effectors
Why the Old Way Overwhelmed Students:
Trying to learn 6 distinct sub-systems in the very first class resulted in cognitive overload. Most students finished zero working mechanics.

New 4-Step Focused Milestones:

  1. Step 1: Import starter package and open 0_startscene.unity.
  2. Step 2: Assemble Player hierarchy with PlayerController2D, PlayerInput, and GroundCheck.
  3. Step 3: Add Cinemachine 2D Camera and assign Follow target.
  4. Step 4: Place Coin prefabs with isTrigger pickup detection.
Why This Is Better:
Builds a clean, playable core loop in 45 minutes. Advanced tools (Tilemaps, Sprite Shapes) are moved to dedicated workshops where they can be properly taught.
6. Troubleshooting & Failure Modes

Diagnostic matrix for common beginner errors

Old Way

Original Content:

No troubleshooting checklist or debugging tips provided.

Why the Old Way Left Students Stranded:
When a character fell through the floor or flipped upside down, students spent hours trial-and-erroring random inspector checkboxes.

New Diagnostic Table:

Symptom Root Cause One-Click Fix
Falls through floor LayerMask mismatch or missing Collider Ensure floor has BoxCollider2D; verify Ground LayerMask
Character tips over Z-axis torque from physics collisions Check Constraints > Freeze Rotation Z on Rigidbody2D
Input unresponsive PlayerInput missing or wrong mode Add PlayerInput component; set Behavior to Send Messages
Why This Is Better:
Empowers students to self-debug immediately without waiting for teacher assistance.
Keyboard Shortcuts: Left/Right Arrow = Navigate Slides | Spacebar = Toggle Old / New Mode
